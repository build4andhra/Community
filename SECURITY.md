# Security Policy

## Scope

Security reports are welcome for code and services maintained by Build4Andhra. Individual repositories may define supported versions and narrower scope.

## Reporting

Do not publish exploitable details in public issues or pull requests. Use GitHub's private vulnerability reporting feature if enabled, or contact maintainers through the private channel published on the organization profile.

Include the affected repository/component/version, impact, safe reproduction steps, and a minimal proof of concept where appropriate. Remove secrets, personal information, and confidential data.

## Coordinated disclosure

Please allow maintainers reasonable time to investigate, validate, remediate, and coordinate disclosure. We will acknowledge reports when possible, assess severity, and communicate material progress.

Do not access, modify, exfiltrate, or destroy data; disrupt services; or test systems outside explicit authorization.

## Authorization boundaries

This policy does not authorize testing of third-party, government, employer, partner, or production systems. Testing requires explicit authorization and an agreed scope. Stop if you encounter data or access beyond your authorization and report it privately.

## Maintainer response

Restrict access to sensitive reports, rotate exposed credentials where needed, coordinate fixes, and publish an advisory when appropriate. Removing a secret from Git history does not make it safe; revoke or rotate it.
