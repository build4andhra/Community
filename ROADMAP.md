# Roadmap

This roadmap is a proposal. Priorities should be refined through public issues and community discussions.

## Phase 1 — Establish the foundation

- [ ] Confirm organization access and secure owner accounts with MFA or passkeys
- [ ] Publish community policies and repository-specific licenses
- [ ] Enable Discussions and issue templates
- [ ] Publish maintainer and contact information
- [ ] Establish private security reporting

## Phase 2 — Make it easy to learn and join

- [ ] Create beginner-friendly issues and onboarding guides
- [ ] Start peer-learning groups and reading circles
- [ ] Publish contribution paths for code, docs, design, testing, translation, and mentoring
- [ ] Host introductory sessions and project demos
- [ ] Create a directory of community learning resources

## Phase 3 — Build and share

Potential tracks:
- software engineering and open-source tools
- AI, machine learning, and responsible AI
- cloud, DevOps, cybersecurity, and infrastructure
- data engineering, analytics, and open data
- Telugu and other language technology
- design, accessibility, and user experience
- education, research, hardware, and interdisciplinary projects

- [ ] Publish project proposals with maintainers and success criteria
- [ ] Encourage reproducible demos, documentation, and maintenance plans
- [ ] Run collaborative build days or hackathons

## Phase 4 — Grow sustainably

- [ ] Develop a mentor and reviewer pathway
- [ ] Document project health, learning outcomes, and community impact
- [ ] Establish partnership and conflict-of-interest procedures
- [ ] Create a lawful accounting and sponsorship arrangement before handling funds
- [ ] Evaluate formal registration only if the community's activities require it

## Project acceptance criteria

Each project should state the problem, intended users, maintainer, license, data provenance, risks, contribution path, and maintenance plan. High-risk or regulated projects require specialist review before deployment.
